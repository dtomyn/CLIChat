Microsoft's Agent Platform, Built for Real: 23 LangGraph Agents on Microsoft Foundry

At Microsoft Ignite, Microsoft described its end-to-end agent platform in one picture: build in GitHub, run and optimize in Foundry, reach people where they work, and feed what you learn back into the next build. I built 23 real LangGraph agents to see what each box on that slide actually takes.

This video redraws Microsoft's picture with the real deployment. It then walks through four architecture views, each followed by the live Foundry portal screen and the real code behind it: inside one agent, repo to running agent, one request end to end, and the improvement loop. It's meant for architects and developers who want to know what it takes to run code-first agents on Foundry, and which parts you write versus which parts the platform provides.

What's covered:
- Microsoft's end-to-end agent platform from Ignite, mapped to a real build (built with Claude Code, stored in GitHub)
- Inside one agent: one graph shape for all 23, a real LangGraph graph, conditional edges, Send fan-out, a self-check loop and human approval with interrupt()
- Repo to running agent: flattening a monorepo for Foundry's code deploy, a generated azure.yaml, the real azd deploy output, and a three-line main.py
- One request in six hops: Lumen, the Responses endpoint and its Azure role check (Foundry Agent Consumer), the Entra agent identity, the guardrail on the model deployment, the state store that makes approvals resume, and tracing
- The improvement loop: AI red teaming found one real failure, a layered fix, a new golden test case, redeploying as version 3 and a clean re-scan
- What it takes: what you write, what Foundry gives you, and what you need to get started
